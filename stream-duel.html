Waiting for both lanes

Both lanes receive exactly the same rows from one tickerplant on this machine. kdb+: an RDB stores the rows and a real-time engine subscribed to the same tickerplant runs the pattern matching in q, with KDB-X's AI libraries and KissFFT loaded through the KX C interface. DuckDB: a Python bridge subscribes over kdb+ IPC (PyKX, no q runtime), appends each batch to an in-memory DuckDB, and runs the same pattern matching after extracting the window with SQL, in NumPy and dtaidistance. DuckDB has no streaming server, so a bridge like this is what a DuckDB deployment has to build.

Both lanes run identical definitions, thresholds and templates; a test checks they return identical numbers on identical rows. Every figure on this page is measured as it happens. Planted events come from the generator's deterministic schedule and are used only to score the lanes.
